# ハンズオン04：MCPで実際の画面を確認させる

対応するガイド：[② §2-5 MCP](../../docs/02_Claudeの機能一覧.md#2-5-mcpmodel-context-protocol)

## 目的

- MCPサーバーを1つ接続し、**接続設定がどこに書かれるか**を確認する
- Claudeの「実装しました、動くはずです」という自己申告ではなく、**MCP経由で実際のブラウザを操作させて動作を確認する**という進め方を体感する

## 前提

- [hands-on/README.md](../README.md) の環境構築（手順1〜8）が完了していること
- 作業ディレクトリは `~/hands-on/sample-project`

---

## 手順

### 1. Playwright用のブラウザを用意する

Playwright MCP はブラウザを実際に起動して操作します。Cloud Shell にはブラウザが入っていないため、先に取得します（数分かかります）。

```bash
cd ~/hands-on/sample-project
npx playwright install --with-deps chromium
```

> `--with-deps` はブラウザの動作に必要なOSパッケージも入れます（`sudo apt-get` が走ります）。Cloud Shell ではそのまま実行できます。

### 2. Playwright MCP を接続する

```bash
claude mcp add -s project playwright -- npx @playwright/mcp@latest --headless
```

- `-s project` は**プロジェクトスコープ**での追加です。設定がプロジェクト直下の `.mcp.json` に書かれ、gitにコミットすればチーム全員で共有できます
- `-s` を省略すると既定の `local` スコープ（自分専用）になり、設定は `.mcp.json` ではなく `~/.claude.json` に書かれます
- `--headless` は画面を表示せずにブラウザを動かすオプションです。Cloud Shell には画面がないため必要です

### 3. 設定ファイルを確認する

```bash
cat .mcp.json
```

おおよそ次のような内容が書かれています。

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest", "--headless"]
    }
  }
}
```

**このファイルが、このプロジェクトで使うMCPサーバーの接続設定を管理しています。** どのサーバーを、どんなコマンドで起動するかが書かれているだけのファイルです。リモートMCPの場合はURLや認証方式がここに入ります（認証トークンを直接書かず、環境変数経由で参照するのが推奨です）。

登録状況はコマンドでも確認できます。

```bash
claude mcp list
```

### 4. 開発サーバーを起動しておく

Cloud Shell のターミナル上部の「+」で**新しいタブ**を開き、そこで開発サーバーを起動しておきます。

```bash
cd ~/hands-on/sample-project
npm run dev
```

このタブは開いたままにしておきます。以降の作業は元のタブで行います。

### 5. セッションを開始し、接続を確認する

```bash
cd ~/hands-on/sample-project
claude
```

初回は「`.mcp.json` のMCPサーバーを使うか」という確認が出ます。承認してください。

```
/mcp
```

`playwright` が `connected` になっていることを確認します。

```
/context
```

`MCP tools` の行が増えていることも見ておいてください。**MCPサーバーを接続すると、そのツール定義がコンテキストを消費します**（ガイド② §2-5 の注意点）。

### 6. UIに機能を1つ追加させる

```
TODO一覧に検索フィルタを追加して。
入力欄に文字を入れたら、タイトルにその文字を含むTODOだけが表示されるようにして。
```

実装が終わったら、**まだ自分でブラウザを見ないでください。** 次の手順でClaudeに確認させます。

### 7. Playwright MCP で実際に動作を確認させる

```
Playwright MCP を使って、http://localhost:3000 を開いて、いま追加した検索フィルタが
実際に動作しているか確認して。検索欄に「完了」と入力したときに絞り込みが効くか、
実際の画面の状態を根拠に報告して。スクリーンショットも撮って、保存先のパスを教えて。
```

サンプルデータは3件（「サンプルプロジェクトを起動する」「TODOを追加してみる」「完了フラグを切り替えてみる」）なので、「完了」で絞り込めば1件だけが残るのが正解です。

Claudeがブラウザを操作し、ページの内容（アクセシビリティツリーのスナップショット）を読み取って報告します。**「1件だけ表示されている」ことをClaudeが画面から読み取って言っているかどうか**を見てください。

スクリーンショットのパスが分かったら、Cloud Shell エディタ（「エディタを開く」ボタン）でそのファイルを開けば画像を確認できます。

### 8. 意図通りでない場合

絞り込みが効いていなかった場合は、そのまま直させてみてください。

```
その結果を踏まえて修正して。修正後、もう一度ブラウザで確認して。
```

**Claudeが自分で結果を見て直せる**ようになっている、という点がここでのポイントです。

---

## 確認ポイント

以下が見えたら成功です。

- [ ] `.mcp.json` がプロジェクト直下に作られ、`playwright` の起動設定が書かれている
- [ ] `/mcp` で `playwright` が `connected` と表示される
- [ ] `/context` に `MCP tools` の消費が現れている
- [ ] Claudeが「実装しました、動くはずです」ではなく、**実際のページの内容を根拠に**動作を報告している
- [ ] スクリーンショットが保存され、追加した検索フィルタが画面に映っている
- [ ] （動いていなかった場合）Claudeが自分で結果を見て修正できている

## ひとことメモ

- ここで使ったのは**ローカルMCP**（自分の環境でプロセスとして起動するタイプ）です。認証が不要な代わりに、動かすための環境（今回はブラウザ）を自分で用意する必要があります。Jira・GitHub・Sentryなどの**リモートMCP**はOAuthやトークンでの認証が必要になります
- MCPは繋げば繋ぐほど便利になる、というものではありません。ツール定義がコンテキストを消費するため、**既存のCLIで代替できない連携に絞る**のが実践上のポイントです（GitHub操作なら `gh` コマンドで足りることが多い、など）
- 顧客のJira・Google Drive等を繋ぐ場合、**技術的に接続できることと、接続してよいことは別問題**です。案件の契約と社内規程を必ず確認してください（ガイド② §2-5 および章④）
